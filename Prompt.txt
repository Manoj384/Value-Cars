# FULL-SCALE APPLICATION AUDIT, TESTING & IMPROVEMENT PROMPT

You are acting as a **Senior Full-Stack Developer, QA Engineer, UX/UI Designer, Security Engineer, Performance Engineer, and Product Manager**.

I have built a second-hand car marketplace application similar in concept to platforms such as Spinny.

Your job is NOT simply to review the source code.

You must **run the complete application, use it like a real customer and admin, identify problems, reproduce them, fix them, and verify that the fixes work**.

Do not make unnecessary architectural changes. First understand the existing application and preserve functionality that already works correctly.

---

# 1. FIRST UNDERSTAND THE APPLICATION

Before modifying anything:

1. Inspect the entire project structure.
2. Identify:

   * Frontend framework
   * Backend framework
   * Database
   * Authentication system
   * APIs
   * Admin panel
   * Image/file storage
   * Payment integration, if any
   * Search system
   * Filtering system
   * Hosting/deployment configuration
3. Understand how the frontend communicates with the backend.
4. Understand database relationships.
5. Identify all major user roles.
6. Identify existing features.
7. Identify unfinished or placeholder functionality.
8. Identify TODOs, console errors, warnings and broken imports.
9. Check environment/configuration files.
10. Do NOT expose or print secrets, API keys, passwords or credentials.

Create a short internal map of the application's architecture before beginning the audit.

---

# 2. RUN THE APPLICATION

Actually start and run the application.

Do not rely only on static code inspection.

Test the application in the browser as an actual user.

Verify:

* Application starts successfully
* No startup errors
* No broken routes
* No blank pages
* No infinite loading
* No unexpected redirects
* No console errors
* No failed API requests
* No database errors
* No broken images
* No missing assets
* No layout crashes

If something prevents the application from running:

1. Identify the root cause.
2. Fix it.
3. Restart the application.
4. Test again.

Continue until the application can be used normally.

For every issue discovered, classify it:

### P0 — CRITICAL

Application cannot run or major functionality is unusable.

### P1 — HIGH

### P2 — MEDIUM

Feature works but has significant usability/performance/reliability issues.

### P3 — LOW

Minor UI, code-quality or polish issue.

Focus on P0/P1 first.
