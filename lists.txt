# SECOND-HAND CAR MARKETPLACE — SPINNY-STYLE PRODUCT IMPROVEMENT PROMPT

I have built a second-hand car marketplace application.

I want to improve it into a **professional, trustworthy, smooth and user-friendly used-car platform inspired by the user experience of Spinny**, but I do NOT want unnecessary complexity.

The application will NOT have:

* Online payment
* Payment gateway
* OTP login
* Multiple admin accounts

There will be:

* One primary admin account — me
* Customer/user accounts
* Email-based account verification
* Password-based login after email approval
* Admin approval workflow
* Car inventory management
* Customer enquiries
* Favorites
* Booking/inspection request functionality if implemented

The goal is to make the application feel like a **real commercial used-car marketplace**, not a basic CRUD project.

NEVER store passwords as plain text.

or

The database must NEVER contain:

Instead store a secure password hash.

# 40. IMPORTANT BUSINESS RULES

Implement these rules strictly:

1. Browsing does not require login.

2. New users cannot create a password until their email verification request is approved.

3. Only the admin can approve verification requests.

4. Users cannot approve themselves.

5. Users cannot access admin APIs.

6. Users cannot modify another user's data.

7. Users cannot modify cars unless they are admin.

8. Passwords must never be stored in plain text.

9. Verification links must expire.

10. Approval links must be single-use.

11. Password reset links must expire.

12. Payment functionality must NOT be added.

13. OTP functionality must NOT be added.
